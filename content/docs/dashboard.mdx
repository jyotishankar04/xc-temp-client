The dashboard is the human review surface for XecureCode. Use it to connect
services, inspect incident evidence, generate RCA reports, approve actions,
review deployments, configure rollback, and audit decisions.

## Workflows

| Area | What you do |
| --- | --- |
| Overview | Use dashboard stats and recent activity to identify current reliability pressure. |
| Services | Create services, map GitHub repositories, configure environments, and manage API keys. |
| Events | Filter raw incident events by service, fingerprint, and time range. |
| Incidents | Review grouped incidents, update status or severity, and merge related cases. |
| RCA | Generate, review, and annotate root cause reports for incident groups. |
| Actions | Approve or reject recommended recovery actions. Rollback approvals queue execution. |
| Rollback | Set rollback thresholds, workflow names, and review rollback history per service. |
| Deployments | Inspect release history, stable versions, and deployment metadata. |
| Notifications | Review incident updates, approval requests, and rollback progress. |
| Audit | Review user, system, and AI activity across the organization. |

## Service setup checklist

- Create one service per deployable application and environment.
- Generate API keys from the service detail page.
- Invite service members when access differs from organization access.
- Connect GitHub before configuring workflow-backed rollback.
- Keep rollback disabled until the workflow and review process are tested.
- Create deployments for each release so rollback can resolve a stable commit.
- Use the notifications inbox when you need to review action approvals later.

## Team workflow

1. Invite organization members from the team area.
2. Add service-specific members when a service needs narrower access.
3. Give rollback permissions only to trusted service admins or owners.
4. Use audit logs after approvals, rejections, and rollback attempts.
5. Review the deployments page before you approve a rollback in production.
