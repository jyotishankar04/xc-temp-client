---
title: Troubleshooting
description: Debug setup, ingestion, auth, and rollback.
---

Most issues come from mismatched API URLs, missing service keys, expired
dashboard sessions, or incomplete GitHub rollback setup. Use these checks before
changing application code.

## Start with health

Check `GET /health` first. It verifies database and Redis connectivity.

## The SDK does not send events

- Confirm the SDK is initialized on the server, not in browser code.
- Check that the API URL points to the backend host.
- Verify that the service ID matches the service you created.
- Confirm that the SDK can reach `POST /api/v1/ingest` or `POST /api/v1/ingest/batch`.
- Call `flush()` before process shutdown in short-lived scripts.
- If you buffer events, make sure the process stays alive long enough to flush.

## Ingest returns unauthorized

- Create a new service API key from the service page.
- Store the key without extra quotes, spaces, or shell escaping.
- Use the key only for `POST /api/v1/ingest`.
- Rotate the key if it was exposed in a client bundle or log file.
- Confirm that the service ID belongs to the same service as the key.

## Dashboard requests redirect to login

- Confirm GitHub OAuth callback settings point to the backend callback route.
- Set `NEXT_PUBLIC_API_URL` to the backend base URL.
- Confirm the backend CORS origin matches the frontend URL.
- Use the refresh route when a session expires.
- If the user keeps signing out after a restart, confirm the JWT secrets are
  identical across runs.

## Rollback does not run

- Connect the organization GitHub integration first.
- Map the service to the correct repository and branch.
- Set the rollback workflow name on the service rollback page.
- Approve the recovery action before triggering rollback.
- Make sure a deployment exists so rollback can resolve a stable commit.
- Check the rollback history page for a blocked, failed, or cooldown status.
